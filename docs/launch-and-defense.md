# Публикация Roomory и подготовка к защите

## Публичная ссылка через GitHub Pages

Приложение статическое: HTML, CSS, JavaScript и локальные картинки. Сборка и серверная база данных для этой версии не нужны.

1. Откройте репозиторий `averkiyeva-nadya/Roomory` в GitHub.
2. Перейдите в **Settings → Pages**.
3. В **Build and deployment → Source** выберите **Deploy from a branch**.
4. Выберите **main** и **/(root)**, нажмите **Save**.
5. Дождитесь успешной сборки Pages. Адрес будет показан в тех же настройках; ожидаемый адрес проекта — `https://averkiyeva-nadya.github.io/Roomory/`.
6. Откройте ссылку в новом браузере и пройдите сценарий «Начать с нуля». После следующих push в выбранную ветку Pages будет обновлять сайт.

В корень добавлен `.nojekyll`. В этой работе публикация не включалась: подготовлены исходники и инструкция.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Свой проект с нуля

При первом открытии новый пользователь выбирает **«Начать с нуля»** или **«Посмотреть пример»**. Пустой проект содержит основной дом и участок без демонстрационных комнат, мебели и вещей. Комнаты добавляются слева. Параметры дома и участка редактируются на странице участка.

Для существующего пользователя доступна кнопка **«Новый проект»**. Перед заменой данных показывается предупреждение и возможность скачать JSON. Простое посещение сайта или обновление версии не сбрасывает существующий проект.

У каждого посетителя данные находятся в его браузере. Аккаунтов и синхронизации устройств нет. Публикация исходников не публикует содержимое localStorage пользователя. При переходе с localhost или HTML-файла на опубликованный домен старые данные автоматически не появятся: сначала экспортируйте JSON на старом адресе, затем импортируйте на новом.

## Можно ли сделать приложение

Да. Ближайший вариант — PWA: манифест с названием и иконками, отдельное окно при поддержке браузером, service worker для продуманного офлайн-кэша, HTTPS и проверка обновлений/резервных копий. Сейчас эти компоненты ещё не реализованы; обычная адаптивная веб-версия уже есть. Установка PWA сама по себе не добавляет аккаунты или облачную синхронизацию.

Официальные материалы:
- https://web.dev/learn/pwa/web-app-manifest
- https://web.dev/learn/pwa/installation
- https://web.dev/learn/pwa/service-workers

## Что готовить к сдаче

Это рабочий список по нашему паспорту/плану проекта и общая подготовка к защите, а не подтверждённая официальная рубрика МАИ. Содержимое исходной папки с заданием через доступный веб-просмотр не удалось прочитать; точные требования нужно сверить с PDF или текстом задания.

- Сформулировать проблему, аудиторию и проверяемые сценарии. Провести настоящие интервью/пользовательские проверки с 3–5 людьми и записать замечания. Поздние проверки не выдавать за интервью до разработки.
- Подготовить пояснительную записку: постановка задачи, аналоги, требования, выбранный стек, схема данных, геометрия и проверки границ, поиск, JSON/локальное хранение, ограничения и результаты тестирования. Объём и оформление сверить с заданием.
- Подготовить доказательства использования ИИ. В README/плане ещё отмечены собственный полезный SKILL.md, документированная передача между ролями и реальный вызов стороннего MCP со скриншотом. Не заявлять эти пункты выполненными, пока нет реальных файлов и результатов. Проверить, что именно требуется преподавателем.
- Обновить план задач: убрать старые противоречивые статусы, приложить актуальные проверки и ограничения, выделить стабильную версию/релиз.
- Подготовить презентацию примерно на 5–6 слайдов: проблема → решение → архитектура/данные → работа с ИИ → демонстрация → проверки и ограничения. Число слайдов сверить с заданием.
- Отрепетировать показ: пустой проект → комната → мебель/полка → вещь → изменение количества из таблицы → поиск → участок/сарай → экспорт/восстановление. Иметь тестовую JSON-копию и короткое резервное видео, если на защите не будет интернета.
