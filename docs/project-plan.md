# Паспорт Roomory · черновик

## Проблема и пользователь

Для человека, который хранит вещи в нескольких шкафах и коробках и забывает их расположение. Сейчас приходится искать вручную или помнить расположение. Это гипотеза: до расширения проекта нужны 3–5 разговоров о реальном опыте поиска вещей.

Основной путь: создать комнату с размерами → разместить мебель → добавить отделения и вещи → ввести название → увидеть нужную мебель и точный путь хранения.

## Три возможности первой версии

1. Редактор прямоугольных комнат и мебели: размеры в метрах, перемещение, поворот на 90°, контроль границ.
2. Места хранения и вещи: отделения, название, количество, заметка, редактирование и перемещение.
3. Поиск по всем комнатам с переходом и подсветкой, локальное сохранение проекта, резервная копия JSON.

## Технический подход

HTML + CSS + обычный JavaScript, без сборки и зависимостей. План — DOM-элементы с процентными координатами; исходная геометрия хранится в метрах. Такой подход подходит для небольшого курсового проекта, позволяет открывать исходники напрямую и использовать настоящие кнопки для управления с клавиатуры. В демоверсии `width/depth` — уже отображаемые размеры; редактор должен определить единое правило пересчёта при повороте.

Хранение первой версии: localStorage с версией схемы и обработкой ошибок. Сервер и аккаунты не нужны. Планируется экспорт/импорт, поскольку данные браузера могут быть удалены пользователем.

## За рамками первой версии

Произвольные стены, автоматическое распознавание планов, 3D, облачная синхронизация, совместный доступ, распознавание вещей по фото, QR-коды. Двери и окно сейчас являются иллюстрацией, а не редактируемыми объектами.

## Критерии готовности

- Пользователь самостоятельно создаёт комнату, мебель и вещь.
- Мебель не выходит за границы после перемещения, поворота и изменения размеров.
- Поиск находит вещь по части названия, открывает нужную комнату и показывает путь.
- После перезагрузки проект восстанавливается; резервная копия восстанавливает его в другом браузере.
- Пустой ввод, неверные размеры, удаление содержимого и ошибки хранения обрабатываются понятно.
- Основной сценарий доступен на узком экране и с клавиатуры.

Проверка пользы: предложить 3–5 людям найти несколько заранее добавленных вещей без подсказок; записать время, ошибки и места затруднений. Целевой ориентир — минимум 4 из 5 находят нужную вещь за 30 секунд в подготовленном проекте. Это план проверки, а не полученный результат.

Для сдачи: согласование темы, README, исходники, свой скилл, подтверждение MCP, материалы реальной пользовательской проверки и презентация на 5–6 слайдов. Состав команды и личный вклад уточняются автором.
